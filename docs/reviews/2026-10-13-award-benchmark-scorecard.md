# 获奖网站排版实测 + Echuu 官网 Awwwards / Webby 打分(2026-10-13)

## 1. 结论速览

| | 估分 | 说明 |
|---|---|---|
| **Awwwards**(加权) | **6.7 / 10** | 刚过荣誉提名线 6.5;创意分高,可用性(性能)拖分 |
| **Webby**(7 项平均) | **6.6 / 10** | 视觉、创新强;功能性(加载、国内可达)最弱 |
| 修完 P0 + P1 后预估 | Awwwards ≈ 7.5 | 主要靠可用性 5.5 → 7.2、设计 7.0 → 7.6 |

> 分数是按两个奖项公开的评分维度做的估计,不是评审结果。评审是人打分,同样的网站不同评审会差 1 分左右。

**最该先修的 5 件事**

1. 首屏 3D 模型首次访问要下载 **13MB**(原文件 30.8MB),而且模型没下完之前「跳过」键是灰的。
2. 打包后的 JS、CSS 文件名带了内容哈希,缓存头却是 `max-age=0`,回访时 80 多个请求每个都要回服务器确认。
3. 「3」用的 Agu Display 和衬线后备字体 Noto Serif SC 只从 Google Fonts 加载,中国大陆打不开。
4. 没有统一的列栅格(对标站多数是 12 列),左边线除了 72px 还有 40 / 64 / 440px 等零散值。
5. 正文字重 300,对标站正文全部是 400 以上;42dot 300 压在天空和白色高光上偏虚。

## 2. 两个奖怎么评

### Awwwards(官方评估页)

| 维度 | 权重 |
|---|---|
| 设计 Design | 40% |
| 可用性 Usability | 30% |
| 创意 Creativity | 20% |
| 内容 Content | 10% |

- 至少 18 位评审打分,去掉离平均最远的 3 个分数。
- 6.5 分以上得荣誉提名(Honorable Mention);每天得分最高的拿当日最佳(SOTD)。
- 当日最佳再交开发者评审,按开发指南打分,7 分以上得开发者奖(Developer Award)。
- 官方页面只给权重,没写每项细则。评审在公开文章里的解释是:设计看版式、字体、配色、层级、一致性;可用性看导航、清晰度、性能、响应式、无障碍。

### Webby(官方评审标准,网站类)

| 维度 | 官方要点 |
|---|---|
| 内容 Content | 文字之外的声音、动画、视频都算;贴合受众、为网页而写 |
| 结构与导航 | 信息组织、优先级、用户怎么在站里移动;一致、直觉 |
| 视觉设计 | 高质量、贴合受众;**要照顾低视力、认知障碍等无障碍需求** |
| 功能 Functionality | **加载快**、链接可用、跨平台浏览器;照顾带宽受限和特殊访问需求 |
| 互动 Interactivity | 不只是悬停和点击,能「给与收」(搜索、聊天、实时反馈);**会问站点怎么用 AI** |
| 创新 Innovation | 是不是真的新、技术能不能用、会不会影响后来者;AI 要用得有诚信 |
| 整体体验 | 大于各部分之和:会不会回访、收藏、订阅、分享 |

官方没公布各项权重和分制,下面按 10 分制、等权估分。

## 4. 从实测归纳出的「标准」

| 项 | 实测结论 | 依据 |
|---|---|---|
| 字体 | **最多 2 种**(一个展示 + 一个正文/等宽) | 8 站全部 ≤ 2;Lusion、Stripe 只用 1 种 |
| 字号 | 一个断点里 4–13 个;整站等比缩放的站会多到 20 个 | 中位约 10 |
| 正文 | 13–20px,中位 15–16;字重 **400**;字距 0 ~ -0.011em | 字距没有一个站是正的 |
| 正文行高 | 拉丁文 1.25–1.6 | 中文没有方块字以外的上下伸部留白,需要更高,1.7–1.8 合适 |
| 大标题 | 行高 **0.8–1.1**(中位 1.0);字距 **-0.02 ~ -0.04em** | 7 个可测站点全部落在这个区间 |
| 全大写小标签 | 实测基本是 **0 字距** | 常见的「全大写加 0.1em 字距」说法在这批站上不成立(Lusion 33 处、Lando 29 处都是 0) |
| 按钮 | 高 40–50px;**每站只用一种圆角族**:要么小圆角 4–8,要么全胶囊 | Linear 是工具型产品,按钮更小 |
| 横向对齐 | **12 列栅格**最常见;左右外边距 1440 宽下 72–136px(5–9.5vw),全出血版式用 16px | 5 站有 12 列 |
| 纵向节奏 | 两派:**严格 4 / 8pt**(basement 95% 是 4 的倍数,Stripe 76% 是 8 的倍数);或**按设计画板整体等比缩放**(Lando、Lusion,像素值是小数) | 共同点是用一套 token,不是随手写数 |
| 基线栅格 | 这批站都没有强制基线栅格 | 网页上靠「行高 × 间距 token」控制节奏 |

**「以什么为标准对齐」的回答**:横向对 12 列(固定栏间距 + 统一外边距);纵向对一套间距 token(4/8pt 或按画板等比缩放二选一);大标题靠紧行高和负字距把字面对到栅格线上(视觉对齐),不追求严格的基线栅格。

## 5. 我们对照标准

| 项 | 标准 | 我们(线上,1440) | 判断 |
|---|---|---|---|
| 字体 | ≤ 2 种 | 3 种:42dot + 蒲瓜纤云宋 + 少量 Inter 残留 | 删掉 Inter 残留 |
| 字号 | 4–13 | 12 | 合格 |
| 正文 | 15–16px,字重 400 | 16px / 行高 1.75 / 字距 0 / **字重 300** | 字号行高合适(中文);**字重偏细** |
| 大标题 | 行高 0.8–1.1,字距 -0.02 ~ -0.04em | 63px / 1.1 / -0.03em | 合格(描边保留,所以取区间里松的一头) |
| 按钮 | 40–50px,一种圆角族 | 36 / 44 / 52px,圆角 12 + 标签 999 | 合格(今天刚统一) |
| 横向栅格 | 12 列 | 没有统一列栅格,只有零散的 1 / 2 / 3 / 5 列 | **缺** |
| 左右边距 | 统一 | 72px 为主,另有 40 / 64 / 440px | 部分不齐 |
| 间距 token | 4pt 派 70–95% | 61% 是 4 的倍数 | 中等 |
| 首屏体积 | 越轻越好 | **3D 模型首次下载 13MB**;JS 共 713KB(gzip) | 严重 |
| 缓存 | 带哈希的资源长期缓存 | `max-age=0, must-revalidate` | 要改 |
| 国内可达 | — | Agu Display、Noto Serif SC 依赖 Google Fonts | 要改 |
| 无障碍基础 | — | `lang=zh-CN`、1 个 h1、标题层级正确、61 张图全有 alt、无无名称控件、支持减少动态效果、有「跳到主要内容」 | 好 |
| 手机端 | — | 中日英韩 390 宽无横向溢出、按钮无截断 | 好 |

## 7. 优化清单(按优先级)

### P0:性能与可达(影响 Awwwards 可用性、Webby 功能)

1. **首屏模型瘦身**:做一份网页专用模型,目标 ≤ 3MB。减面、贴图转 KTX2 或压成 WebP、用 meshopt 压缩,去掉网页用不到的表情和骨骼。
2. **跳过键不等模型**:现在跳过键要等模型加载完才能点。改成随时可跳,先显示首屏定格海报图,模型在后台加载完再无缝接上。
3. **缓存头**:`/app-build/*` 和带版本号的模型、贴图设成 `Cache-Control: public, max-age=31536000, immutable`(在 `vercel.json` 里配)。
4. **国内字体**:Agu Display 和 Noto Serif SC 改为自托管子集,不再依赖 Google Fonts。

### P1:设计细节(影响 Awwwards 设计)

5. **建立 12 列栅格**:外边距 72px(5vw)、栏间距 24px,各区块对齐到列线;修掉 40 / 64 / 440px 这些零散左边线。
6. **正文字重 300 → 400**:所有对标站的正文都是 400 以上。
7. **删掉 Inter 残留**:字体回到 2 种。
8. **间距 token 化**:组件内间距统一用 4 的倍数(现在 61%,目标 85% 以上)。
9. **收敛玻璃和阴影**:只保留 Figma 稿里画了的(排版审计里已列,待设计师确认)。

### P2:内容与互动(影响内容分、Webby 互动 / 整体体验)

10. **真实产品画面**:直播间实录短片、创作者作品墙(署名、取得授权)、能说清楚的具体数字。
11. **站内可玩**:让访客跟示例角色说一句话、看 AI 实时反应。Webby 的互动和创新两项都明确问 AI 用法。
12. **把负责任 AI 摆上首页**:AI 内容说明和创作者权益已经有文档,在首页给一个清楚的入口。
13. **提交前专门过一遍手机端开场**:评审会用手机看。

## 8. 方法与局限

- 样本 8 个站,只测首页、只测 1440 一个断点;对标站的「获奖身份」已按能核实的程度标注。
- 「间距是 4 的倍数」这个指标对整站等比缩放的站会失真(像素值是小数),所以只当参考,不当硬标准。
- 我们的体积数据:浏览器对部分缓存资源不报大小,所以 JS 体积用的是同一次提交的本地构建 gzip 大小,模型用 curl 实测 brotli 传输大小。
- 打分是按公开评分维度做的估计,用来排优先级,不代表评审结果。
